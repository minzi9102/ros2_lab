# ws_pen_writing_control 签字笔书写控制计划

本文档记录“在 UR3e 末端安装签字笔，并通过 Xbox 手柄控制机械臂写字”的分阶段实现计划。

当前只做计划归档，不创建 ROS 2 package，不实现代码，不进行真机动作。

## 1. 目标

最终目标：

```text
Xbox 手柄 -> 控制笔尖在纸面移动 -> 笔身随运动方向保持合适倾斜 -> 在纸上写出可控线条和简单文字
```

这个任务不是普通遥操作。写字需要同时满足：

- 笔尖位置沿纸面移动得准。
- 笔尖能稳定接触纸面，但压力不能过大。
- 笔身姿态要随运动方向变化，像人写字一样“拖着笔尖走”。
- 所有真机动作必须受工作空间、速度、姿态和接触安全限制。

## 2. 新工作区定位

建议新建工作区：

```text
workspaces/ws_pen_writing_control
```

定位：

```text
ws_pen_writing_control = 笔尖工具建模、纸面坐标系、书写姿态控制和写字验收入口
```

它与 `ws_realtime_control` 的关系：

- `ws_realtime_control` 已验证键盘、evdev、Xbox 手柄到 MoveIt Servo 的实时遥操作链路。
- `ws_pen_writing_control` 聚焦“签字笔工具 + 纸面 + 接触式书写任务”。
- 不把写字逻辑直接塞进通用手柄控制包，避免把普通遥操作和接触式任务混在一起。

## 3. 核心设计判断

写字控制的关键参考点不是裸 `tool0`，而是笔尖：

```text
tool0 -> pen_tip
```

必须先建立笔工具模型：

- `pen_tip` 相对 `tool0` 的位置偏移。
- 笔身轴线相对 `tool0` 的方向。
- 推荐书写倾角，例如笔身相对纸面法线倾斜 15-30 度。
- 笔尖安全接触高度、抬笔高度和纸面安全边界。

姿态策略第一版采用：

```text
笔尖接触纸面
笔身朝运动方向的反方向倾斜
运动方向改变时，笔身 yaw 跟随改变
倾斜角保持固定
```

直观语义：

- 往 `+X` 写时，笔杆向 `-X` 后方倾。
- 往 `+Y` 写时，笔杆向 `-Y` 后方倾。
- 对角线运动时，笔杆向对角线反方向倾。
- 停止或抬笔时，姿态不应突变。

## 4. 分阶段路线

### 阶段 1：虚拟笔模型与 RViz 姿态验证

目标：

```text
在 fake hardware + RViz 中看到一个虚拟 pen_tip / pen_axis，确认姿态数学正确。
```

任务：

- 建立 `pen_tool_model` 配置。
- 发布或显示 `pen_tip` 与笔身方向 marker。
- 左摇杆控制笔尖在平面内移动。
- 根据平面速度计算笔身 yaw 和固定倾斜姿态。
- 不接触真实纸面，不考虑力控。

验收：

- `+X / +Y / -X / -Y / 对角线` 运动时，笔身始终向运动反方向倾斜。
- 松开摇杆后，笔尖停止，姿态无突变。
- RViz 中能清楚区分 `tool0`、`pen_tip`、纸面和笔身方向。

### 阶段 2：URSim 姿态链路验证

目标：

```text
在 URSim 中验证 MoveIt Servo / driver 链路能执行带姿态变化的写字姿态控制。
```

任务：

- 复用 `ws_realtime_control` 的 URSim 启动经验。
- 使用低速、无接触、短时会话。
- 只验证末端姿态跟随与平面运动，不验证真实书写。

验收：

- URSim 网页监视器中能看到末端随运动方向倾斜旋转。
- 手柄停止、A 急停、B 退出都能保持安全行为。
- 出现 singularity / collision / emergency stop 日志时立即停止并记录。

### 阶段 3：真机空中写字演示

目标：

```text
在真实 UR3e 上方空中演示笔尖轨迹和姿态，不接触纸面。
```

前置条件：

- 通过 Stage 4 只读状态门闩。
- 真实机器人处于 RUNNING / NORMAL。
- External Control 正在运行。
- 低速、短时、人工确认、急停可触达。

任务：

- 安装签字笔但保持笔尖离桌面数厘米。
- 用手柄画直线、折线、圆弧。
- 验证姿态平滑、无突变、无频繁奇异位形保护。

验收：

- 笔尖空中轨迹与手柄输入方向一致。
- 笔身倾斜方向符合运动反方向。
- 不接触纸面，不产生真实书写压力。

### 阶段 4：纸面与笔尖标定

目标：

```text
建立 paper_frame 与 pen_tip 标定，使系统知道纸面在哪里、笔尖在哪里。
```

任务：

- 标定纸面坐标系 `paper_frame`。
- 标定 `tool0 -> pen_tip`。
- 定义安全工作区域，例如纸面上的小矩形。
- 定义落笔高度、书写高度、抬笔高度。
- 决定第一版是否使用固定 z，还是加入柔顺/力控方案。

验收：

- 系统能在 RViz 中显示纸面边界和 pen_tip。
- pen_tip 与真实笔尖位置误差在可接受范围内。
- 超出纸面边界的命令被拒绝或限幅。

### 阶段 5：真实接触写线条

目标：

```text
在纸面上以低速写出直线、折线和简单曲线。
```

任务：

- 从极低速度开始。
- 使用小范围纸面区域。
- 优先写短直线，再尝试圆弧和简单字母。
- 记录笔迹质量：断墨、刮纸、压力过大、线条抖动、姿态滞后。

验收：

- 能画出连续短线。
- 笔尖不会明显刮破纸面。
- 手柄停止后笔尖立即停止或抬笔。
- 任何异常都能通过 A、B、急停或 launch shutdown 停止。

## 5. 候选控制方案

### 方案 A：继续使用 MoveIt Servo Twist

优点：

- 延续当前 `ws_realtime_control` 链路。
- 手柄响应快。
- 已经验证 fake hardware、URSim 和部分真机键盘路径。

代价：

- 固定笔尖在纸面和固定倾斜角比较难。
- `tool0` 与 `pen_tip` 的偏移会让直觉控制变复杂。
- 接触式写字时，单纯 Twist 不处理压力。

### 方案 B：小步目标 Pose 控制

思路：

```text
手柄输入 -> 更新 pen_tip 目标 pose -> 计算 tool0 目标 pose -> MoveIt / Servo 跟踪
```

优点：

- 更适合纸面约束、笔尖约束和姿态约束。
- 易于表达“笔尖在纸面、笔身固定倾角”。
- 后续扩展自动写字路径更自然。

代价：

- 实现复杂度更高。
- 需要验证实时性、平滑性和规划/伺服稳定性。

建议：

```text
阶段 1 先用 fake hardware 验证数学和 RViz 可视化。
阶段 2 再决定继续 Twist 方案，还是切到小步 pose 控制。
```

## 6. 最小模块规划

后续如果进入实现，建议从以下模块开始：

```text
pen_tool_model
  描述 tool0 -> pen_tip、笔身轴线、默认倾角

writing_pose_controller
  输入平面速度 vx/vy
  输出期望笔尖姿态：yaw 跟随运动反方向，tilt 固定

paper_frame_calibration
  描述纸面坐标系、纸面边界、书写高度、抬笔高度

pen_visualization
  在 RViz 中显示 pen_tip、笔身方向和纸面边界

writing_safety_gate
  限制速度、角速度、工作空间、z 高度、会话时间
```

第一版不做：

- 自动生成汉字轨迹。
- 视觉识别纸面。
- 力控闭环。
- 长时间连续写字。
- 真机自动恢复。
- 高速书写。

## 7. 安全边界

真实写字属于接触式任务，比空中遥操作更危险。

必须遵守：

- 真机接触前先完成 fake hardware、URSim 和空中真机演示。
- 真机阶段必须低速、短时、人工确认。
- 不自动解除 protective stop。
- 不自动恢复安全状态。
- 不无人值守运行。
- 不在未标定纸面上落笔。
- 不让笔尖越过纸面安全区域。

接触纸面前必须明确：

```text
纸面在哪里
笔尖在哪里
最大速度是多少
最大角速度是多少
最大下压深度或力是多少
如何立即停止
如何抬笔退出
```

## 8. 当前建议的下一步

下一步不要直接写真机代码。

建议先实现：

```text
虚拟笔模型 + RViz marker + fake hardware 手柄控制下的姿态可视化
```

完成标准：

- RViz 中可以看到纸面、笔尖和笔身。
- 左摇杆控制笔尖在虚拟纸面上移动。
- 笔身随运动方向朝反方向倾斜。
- 不创建真机 launch。
- 不发送真实机器人接触命令。
